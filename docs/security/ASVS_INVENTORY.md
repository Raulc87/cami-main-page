# ASVS_INVENTORY

Appendix to [`SECURITY_BASELINE.md`](SECURITY_BASELINE.md) §2: every OWASP ASVS 5.0.0 requirement
of level 1 and level 2 (253 requirements), one row each, with its coverage or the reason it
does not apply. The level and the reasons are in the baseline.

- Source: the official OWASP ASVS 5.0.0 requirement list (`OWASP_Application_Security_Verification_Standard_5.0.0_en.csv`
  in the `OWASP/ASVS` repository, tag `v5.0.0`); the requirement text is quoted as published.
- IDs are versioned, `v5.0.0-<chapter>.<section>.<requirement>`, so a reference stays valid when
  ASVS changes.
- `SAC-NN` is a security acceptance criterion in the baseline §3, proposed for
  [`USER_STORIES.md`](../specs/USER_STORIES.md) → Security.
- **Planned (PTES test)**: the control is designed in the specs or the code; its code was reviewed
  in the pre-test security review on 2026-10-27 (CMP-063, [`PRETEST_REVIEW.md`](PRETEST_REVIEW.md)),
  and its behavior on a running system is verified by the penetration test (owner decision
  2026-10-27), which records the date.
  **Verified (document review)**: the requirement asks for documentation, and the named document
  holds it. **Accepted risk**: the control is the hosting provider's and cannot be configured by
  the project, or the owner accepted the gap; listed in the baseline §7. Following ASVS is a
  practice, not a certification: this inventory says what is covered and how, not that the
  project is secure.
- Summary: Planned: 83 · Verified (document): 12 · Accepted risk: 13 · Not applicable: 145.
