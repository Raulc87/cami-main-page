## Findings so far

- **OCR works on a real sample** (sample1: `ok`, account and amount found, 4.3 s). The three other files hit `User rate limit exceeded for OCR` when run back to back, so Drive limits OCR per user (the account that owns the script). The spike now retries with a pause of 5, 10, 20, 40 s and waits 3 s between files.
- **Production implication (FFR-017 runs OCR per registration after the lock):** a burst of registrations can hit the same limit. In-execution backoff fits inside the 6-minute limit for small bursts. If the retries are exhausted, FFR-017 and the contract define only `ok`, `mismatch` and `unreadable`, and `pending`; marking such a row `unreadable` would send the participant a "payment not validated" email for a service limit. Leaving it `pending` and retrying later by a time trigger is not in the spec. **Owner decision (2026-10-20, via the coordinator, option a):** after the in-execution retries, leave the check `pending`, send no email, and retry the pending rows with a time-driven trigger. The coordinator records it as FFR-032 and US-022 AC6 (PR #30) and adds it to CMP-028's scope, including a runbook step to install the trigger.

- **Owner decision on the alias (2026-10-20):** "add the permission for no-reply@". `gmail.settings.basic` is added to the manifest. Its reach: the script can read and change the owner's Gmail settings (filters, forwarding, send-as aliases), on an anonymous web app that runs as the owner, so nothing but this repo's code may ever run in the project. The fallback sender the owner saw was `camila@lifetoolscr.com`. The `no-reply@` address must be verified as a "Send mail as" alias in that account's Gmail for the retest to work.
- **Sender alias (step e), first run:** `GmailApp.sendEmail` with `from: no-reply@lifetoolscr.com` failed with "Specified permissions are not sufficient"; the error lists `mail.google.com`, `gmail.settings.basic`, `gmail.readonly` or `gmail.modify`. The manifest has only `gmail.send`, so the failure is the scope Apps Script needs to check the alias against the account's "Send mail as" list (`getAliases`), not a missing paid seat. The fallback send from the account itself worked (quota 1499 left). Options: (1) add `gmail.settings.basic`, the narrowest listed scope, re-authorize and retest; it lets the script read and change Gmail settings of the owner's account (filters, forwarding), a wider permission on an anonymous web app that runs as the owner; (2) send from the account with display name and reply-to `camila@lifetoolscr.com`, which needs no extra scope and is the decided fallback. The owner chooses; not changed yet.
- **HEIC (step d), first run:** `heicProbe` on `sample4_2000.heic` reported MIME `image/jpeg`, `getAs('image/jpeg')` ok and OCR text found (2.8 s). That does not prove HEIC support: Drive reports `image/jpeg`, so the file was probably converted or was already a JPEG with a `.heic` name (the iOS Drive app and iOS Photos export convert by default). The probe now logs the file signature to tell them apart. The step stays open until a true HEIC (`ftypheic`) is probed. For the visitor's browser: iOS Safari converts HEIC to JPEG for `<input type=file accept="image/*">` unless the input names `.heic`; not yet tested through the web app.
